# SK하이닉스 본주·ADR 괴리율 대시보드

SK하이닉스 본주(KOSPI `000660`, KRW)와 나스닥 ADR(`SKHY`, USD)을 30분봉으로 나란히 보고, 원/달러 환율로 환산한 괴리율을 추적하는 Streamlit 대시보드입니다. 데이터는 yfinance에서 수집해 저장소의 CSV로 축적합니다.

## 프로젝트 소개

화면은 세 개의 차트로 구성됩니다.

- 본주 30분봉 가격 차트 (KRW)
- ADR 30분봉 가격 차트 (USD)
- 괴리율(패리티) 차트

괴리율 산식은 다음과 같습니다.

```
ratio = 본주가격 / (ADR가격 × 10 × 원달러환율)
```

ADR 10주가 본주 1주에 해당합니다(`SKHY`, 2026-07-10 나스닥 상장). 이론상 ratio는 1.0 근처여야 하지만, ADR 전환한도(발행주식의 2.5%)가 소진되어 본주→ADR 전환 차익거래가 막혀 있습니다. 그 결과 ADR에 구조적 프리미엄이 붙어 ratio는 1.0을 크게 밑돕니다 — 2026년 7월 실측 기준 대략 0.63~0.88(ADR 프리미엄 약 +14~58%)이며 일중 변동이 큽니다. 이 수치가 1.0에 수렴하지 않는 것은 데이터 오류가 아니라 시장 구조입니다.

## 아키텍처

```
GitHub Actions (평일 2회 cron)
        │
        │  scripts/update_data.py 실행
        ▼
   data/*.csv 갱신 ──커밋·push──▶ GitHub 저장소 (영구 저장소)
                                        │
                                        │  push가 자동 재배포 유발
                                        ▼
                            Streamlit Community Cloud
                                        │
                     저장소 CSV(축적분) + 런타임 yfinance 5일 top-up 병합
                                        ▼
                                   대시보드 화면
```

- 저장소의 CSV가 유일한 영구 저장소입니다. Streamlit Cloud의 파일시스템은 재배포 때마다 초기화되므로 앱은 저장소 CSV를 읽고, 최신 구간만 런타임에 yfinance 5일 top-up으로 메웁니다.
- yfinance의 30분봉은 최근 60일까지만 제공됩니다. GitHub Actions가 평일 2회 60일 창을 통째로 다시 받아 기존 CSV와 병합·커밋하므로, 저장소에는 60일 한도를 넘는 이력이 계속 쌓입니다.
- `scripts/update_data.py`는 첫 실행이 곧 60일 백필이고 이후 실행은 증분 갱신입니다. 동일 코드로 멱등하게 동작해, 실행이 오래 끊겨도 다음 실행에서 스스로 복구합니다(단 60일 초과 공백은 복구 불가).

## 데이터 정책

- 원시 체결가만 저장합니다(`auto_adjust=False`). 배당락 시 과거 가격이 소급 조정되면 이미 저장한 CSV와 어긋나고 당시 실제 거래 가격도 아니게 되므로, 조정을 적용하지 않습니다.
- 정규장만 수집합니다(`prepost=False`). 프리·애프터마켓 체결은 제외합니다.
- 완결봉만 저장합니다. 봉 시작 시각 + 30분이 현재(UTC)를 지나야 저장 대상입니다.
- Yahoo 무료 시세는 지연·정정이 있을 수 있습니다. 매매 판단용 실시간 시세가 아닙니다.
- **본주 마감 동시호가 미반영**: Yahoo의 `000660.KS` 30분봉은 하루 12개(시작 시각 09:00~14:30 KST, 커버 구간 09:00~15:00)로 끝나고, 15:00~15:30 구간(마감 동시호가 포함) 봉이 없습니다 (2026-07-31 실측 — 예: 07-29 공식 종가 1,401,000원 vs 30분봉 마지막가 상이). 따라서 미국 장중 괴리율에 이월되는 본주 가격은 공식 종가가 아니라 **15:00 KST 가격**이며, 동시호가 변동분만큼 오차가 생깁니다. 미국 쪽은 마지막 30분봉이 16:00 ET 종가를 포함하므로 이 한계는 본주 쪽에만 있습니다.
- KRX 세션과 미국 세션은 벽시계 기준으로 절대 겹치지 않습니다. 따라서 괴리율의 한쪽 다리는 항상 직전 세션 종가의 이월값입니다. 차트의 세션 밴드는 어느 시장이 열려 있던 구간인지, 이월 표시는 어느 다리가 멈춘 값인지 보여줍니다. 예: KRX 장중의 괴리율 변동은 본주 가격과 환율만 움직인 결과이고, ADR 가격은 전일 미국 종가입니다.
- 미국 서머타임(DST) 때문에 미국 세션의 KST 시각은 연 2회 이동합니다. 코드는 세션 시각(09:00, 22:30 등)을 하드코딩하지 않고 봉의 존재 자체로 세션을 관측하므로 자동으로 따라갑니다.

## 데이터 스키마

| 파일 | 종목 | 티커 | 통화 |
|---|---|---|---|
| `data/kr_000660.csv` | SK하이닉스 본주 | `000660.KS` | KRW |
| `data/us_skhy.csv` | SK하이닉스 ADR | `SKHY` | USD |
| `data/fx_usdkrw.csv` | 원/달러 환율 | `KRW=X` | KRW per USD |

세 파일의 컬럼은 동일합니다.

| 컬럼 | 의미 |
|---|---|
| `ts_utc` | 봉 시작 시각, UTC, `YYYY-MM-DDTHH:MM:SSZ` (:00/:30 격자) |
| `open` `high` `low` `close` | 원시 체결가 (소급 조정 없음) |
| `volume` | 거래량 (환율은 0) |

- `ts_utc` 오름차순 정렬, 중복 없음.
- 같은 `ts_utc`가 다시 수집되면 최신 값으로 덮어씁니다(keep-last). Yahoo의 사후 정정을 그대로 반영하기 위한 정책입니다.

## 로컬 실행

```bash
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

데이터 수집(첫 실행 = 60일 백필, 이후 = 증분 갱신):

```bash
.venv/bin/python scripts/update_data.py
```

대시보드 실행:

```bash
.venv/bin/streamlit run streamlit_app.py
```

테스트:

```bash
.venv/bin/python -m pytest -q
```

## 배포 절차

1. GitHub 저장소를 만들고 push합니다.
2. [share.streamlit.io](https://share.streamlit.io)에서 **New app** → 저장소 / `main` / `streamlit_app.py`를 선택합니다.
3. **Advanced settings**에서 Python `3.12`를 선택하고 **Deploy**합니다.
4. secrets는 필요 없습니다. yfinance는 인증 없이 동작합니다.

배포 후에는 GitHub Actions의 데이터 커밋 push가 Streamlit Community Cloud의 자동 재배포를 유발합니다. 이것이 의도된 데이터 갱신 경로입니다.

## 운영 주의

- **수동 갱신**: GitHub 저장소의 **Actions 탭 → update-data → Run workflow**로 언제든 즉시 실행할 수 있습니다(`workflow_dispatch`).
- **cron 자동 비활성화**: GitHub 무료 계정은 저장소에 60일간 활동이 없으면 예약 워크플로를 자동으로 끕니다. 이 워크플로는 데이터를 자가 커밋하므로 정상 운영 중에는 활동이 계속 갱신되어 문제가 없습니다. 다만 전면 장애로 커밋이 장기간 멎으면 cron이 꺼질 수 있으니, 그때는 Actions 탭에서 워크플로를 수동으로 다시 활성화해야 합니다.
- **실패 알림**: 세 종목이 모두 실패하면 스크립트가 exit 1로 종료하고 GitHub이 실패 메일을 발송합니다. 일부만 실패하면 성공분을 커밋하기 위해 exit 0으로 종료하므로, 가끔 Actions 로그를 열어 개별 종목 오류가 없는지 확인하세요.
- **staleness 배너**: 앱 상단에 배너가 뜨면 마지막 봉이 3일 넘게 갱신되지 않았다는 뜻입니다. 연휴가 아니라면 Actions 실행 이력을 점검하세요.
